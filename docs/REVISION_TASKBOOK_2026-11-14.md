## 1. 结论与修改目标

2026-11-14 初稿的判断是：主线能走完，但选择缺少后果，三阶段操作相似，作品没有保留痕迹。2026-11-15 已以实际表面网格和文化馆灵感连接改善这三项；原图还原与玩法趣味仍按后文方法验收。

建议将核心体验确定为：**因材施艺——看懂一块玉的特点，决定如何利用它，亲手做成一件能看出自己选择的作品。**

改造成功应能看见三个结果：

1. 同一块原石，采用两种合理方案，会得到外观和表达不同的作品。
2. 琢形、雕纹、抛光分别处理轮廓、纹路、表面，玩家能说出三者的操作差别。
3. 游戏运行画面的布局、材质、人物比例和像素尺度能逐项对应 GitHub 概念图；实际作品从加工到展出保持一致。

此前自动测试和构建记录是功能基线；本轮最终结果以最新交接为准。玩法趣味、原图贴近程度和手感需要另行验收，不能用测试数量代替。

## 4. 核心玩法修改方案

### 4.1 一条有因果关系的主线

**收到心意委托 → 找到适合的原石 → 观察色带与裂隙 → 安排器型和纹样 → 琢形、雕纹、抛光 → 留下独有作品 → 展签说明与主题陈列。**

建议先实现一个完整案例：一块有深色斑与边缘裂隙的翡翠，可以把色斑保留为鱼眼，也可以将色带安排在鱼背。缩小或旋转纸样能避开裂隙，但成品的大小、色彩分布随之变化。玩家刻上云纹，选择局部较亮的抛光效果。展厅和导出图应能看出这一块原石及这一次制作留下的特征。

首个案例选择玉鱼佩，便于看出方向和色斑的设计价值；原有玉璧、玉印继续保留，随后接入相同数据链路。单器型样板只是中间验证步骤。

### 4.2 原石与采矿：让找玉有目的

- 保持一张地图、六处玉脉簇、十二块玉、两类材料；先人工设计十二块样本，避免随机生成不可用原料。
- 每块原石具有稳定 ID、外轮廓、色带区域、裂隙路径与来源矿簇。第一轮只让色带和裂隙影响设计；硬度、真实光学和复杂断裂暂不模拟。
- 每块样本至少存在一种安全布局，样板材料应存在两种各有价值的布局。制作十二块原石 × 三器型的可行矩阵，保证至少存在三块互异原石，分别适配玉璧、玉鱼佩和玉印；首展不能依赖同一块唯一适用原石。
- 洞内可以看见粗略颜色和形状，鉴赏台再揭示更细信息。矿脉提示给出“适合宽面”“有集中色斑”等观察线索，不直接宣布唯一答案。
- 采矿保留已有挖掘机制，优先改善路线可读性、矿脉辨识和反馈。六簇所在区域用岩壁形态、光线和道具区分，避免重复梯井成为全部体验。

### 4.3 鉴赏：让观察帮助制作

- 以 05 的大圆形观察窗为主视觉，放大镜移动后显示对应位置；透光切换显示色带范围和裂隙示意。
- 玩家可以标记一条裂隙、圈选一块色带；这些标记带入设计界面。
- 保留两类材料各三个热点与六道知识题。题目放入知识卡，显示与当前观察相关的解释和来源。
- 建议将主线学习条件从只统计答题，调整为“完成观察记录并使用一条线索”；六题依然保留复习与知识收录功能。这属于任务条件调整提案。
- 不把教学示意包装成真实玉石鉴定，也不让生僻知识题阻断手作。

### 4.4 设计：增加少量有意义的选择

- 三种器型使用预设轮廓。玩家在玉料上平移、旋转和有限缩放纸样，预览保留色带、余料和裂隙交叉位置。
- 保持二维遮罩实现，不引入任意三维切割、物理破碎或完整自由建模。
- 设计提示解释选择：“这样能保留鱼背的青色”“这一处边缘接近裂隙”。不直接给统一最优评分。
- 云纹、龙纹、谷纹的选择及位置、方向安排放到雕纹之前。定制界面可在设计阶段进入，最终仍保留定制模块。
- 提供默认方案和辅助轮廓；熟悉操作后可关闭辅助。所有可选方案须在画面中显出区别。

### 4.5 三阶段加工分别重做

| 阶段 | 核心动作 | 真实变化 | 完成依据 |
| --- | --- | --- | --- |
| 琢形 | 粗工具去余料，细工具修边；处理玉璧内孔等指定区域 | 余料逐步消失、轮廓和边缘细节变化，色带随保留区域留下 | 指定余料去除、关键结构保留、轮廓误差；不使用全表面覆盖率 |
| 雕纹 | 沿已布局的纹样刻线，分段完成，可选择有限深浅档 | 实际线迹和偏离可见，形成可辨认的云纹、龙纹、谷纹 | 目标线段连通与完成情况；扫满整块玉不能直接过关 |
| 抛光 | 先处理粗糙处，再用细工具整理；选择整体温润或局部较亮的表面 | 局部粗糙度和高光改变，纹样与天然色带保留 | 达到所选表面风格的处理要求；保留自然区域也能形成合格方案 |

初稿曾提出 128×128 或原有 240×240 网格。当前实现采用 **64×64** 局部状态网格，由统一数据驱动画面与判定，并按扫过的路径处理笔画。更高分辨率是否有必要，待实际手感和存储预算验证后决定。

工具有可见的接触头、动作和短反馈。琢形产生碎屑，雕纹呈现沟槽与局部暗边，抛光呈现渐变光泽；方形刷框只能作为可关闭的辅助范围。

继续采用无倒计时、失误不销毁材料、允许重试的节奏。提供撤销当前笔画、重做当前阶段、暂停保存三个独立动作。完工评价分别描述轮廓、纹样与表面，并指出一项成功选择和一项可改进之处。

### 4.6 作品与定制：让手工结果留下来

- 为成品保存原石特征、纸样布局、实际轮廓、雕纹路径、表面状态及制作摘要。
- 加工预览、背包详情、展柜近看和 PNG 调用同一作品绘制逻辑；小图可以简化细节，不能换成另一套轮廓或纹样。
- 龙纹需要可辨认的头部和身体结构，云纹和谷纹需要各自的节奏，替换当前简单折线或方格造成的混淆。
- 最后定制保留祝福语、作品命名、配色与展示预览。建议将配色限制在玉料本身色域及展示配件，保留天然色带；不能一键覆盖原料特征。
- 雕纹完成后更换纹样需回到相应制作步骤并保留恢复点，不直接在成品上替换一张贴图。
- 保留当前最多 24 字祝福语和 PNG 导出能力，避免恢复早期文档 2–8 字限制而损失已有功能。

### 4.7 委托、图鉴与展厅：为作品提供具体理由

建议三个短委托分别承载三种器型。下列为游戏故事草案，文化寓意须区分剧情表达与有来源的知识。

| 委托草案 | 设计目标 | 两种可接受方案示例 |
| --- | --- | --- |
| 远行人的鱼佩 | 轻巧、有可识别的天然特色 | 色斑作鱼眼；色带作鱼背 |
| 家中的一枚玉璧 | 完整、安静、适合赠礼 | 保留连续色环；保留局部云色并配简洁纹样 |
| 学徒的第一方印 | 稳重、清楚、有个人记号 | 小面积清晰纹样；保留自然玉色并强化印钮轮廓 |

反馈根据实际选择生成，例如“青色被保留在鱼背，云纹没有遮住天然色带”。先使用有限、可验证的规则文案，不依赖实时 AI。

展厅保留三个展位，增加作品名称、短展签和“原石—设计—成品”记录。基础主题先提供“因材成器”，通过摆放顺序与展签串联三件作品；多主题和观众自由对话放后续。

### 6.2 关键数据与恢复规则

- 原石：身份、材质、来源、样本版本、轮廓、色带、裂隙、观察标记。
- 制作草稿：材料快照、器型布局、纹样布局、实际轮廓、刻线、表面、当前阶段、有限长度撤销记录。
- 成品：沿用材料身份，保存作品状态、祝福、名称、制作摘要；展位引用成品 ID。
- 保存编码设置大小上限，不把每次鼠标事件或无限历史写进存档；先测最复杂作品和百件作品的实际存储量。
- 旧档迁移前保留备份。旧原石可用稳定 ID 映射默认样本；旧成品保留原样并标记旧版作品，不虚构玩家从未做过的切割或观察。
- 旧加工中的覆盖率无法可靠还原新工艺，提供“按原流程完成”或“返还同一块材料后重新制作”的明确入口。
- 暂停保存不改变草稿；重做当前阶段回到该阶段检查点。新作的“撤销整次制作”清除本次草稿并返还原石；成品返工的“取消返工”恢复原成品，不返还原石。原石与成品不能同时存在，也不能通过重做复制。
- 已完成作品返工沿用原 ID，暂时移出展位并保存成品与原展位快照。允许选择回到原料快照重新安排器型，并作废依赖旧轮廓的刻线和抛光；完成后以同一 ID 替换原成品。取消返工时恢复成品及原展位，原展位若已放入其他作品则保留该作品并将恢复的成品放回收藏，不擅自覆盖。
- 首展当前条件按实际成品与展位重新计算；已经取得的首次完成记录和知识收录保留，奖励不重复结算。明确区分“曾经完成首展”和“当前展览满足三器条件”。

## 7. 验收方法

### 7.1 玩法验收

建议邀请 3–5 位未参与开发的人，先体验代表流程，再体验三器首展。记录实际时长、需要口头帮助的位置及主动选择，不用“觉得挺好”代替观察。

- 同一块样板玉料至少产生两件明显不同、都能交付的作品。
- 玩家能解释至少一项“因为看到了什么，所以这样设计”的选择。
- 玩家能分别说出琢形、雕纹、抛光的目标；三阶段无需靠更换按钮名称来区分。
- 试玩者能在展厅和导出图片中认出自己制作的作品。
- 首件成器到展出以约 10–15 分钟为待验证目标；三器首展时长另行记录，不把三件流程都强塞进该时长。
- 建议初始通过条件为至少 3/5 试玩者无需口头指引完成首件作品，并能说明一种材料取舍。人数不足时保留实际样本数，不宣称整体玩家结论。
- 若样板仍只能靠重复拖动增加进度，返回 R04–R07 修改规则，再开展全量美术和内容。

### 7.2 视觉验收

用户提出的基础 UI 与弹窗 95% 接近目标继续保留，最终以原图对照与用户评审确认。当前没有已完成的相似度测量。

每屏提交：GitHub 原图、运行截图、同尺寸并排图、50% 透明叠图、主元素边界框、差异清单。先对齐游戏画幅、界面状态和缩放，不把浏览器外框纳入比较。

07/08/09 按原图对应区域直接配准验收；04/05 和加工近景以用户确认的适配稿检查运行布局，同时另附“原图—适配稿”的元素映射与差异说明。适配稿验收不能替代对 GitHub 原图还原方向的评审，不得将跨画幅原图强行拉伸后比较。

建议初始几何容差：关键大区域位置与尺寸误差不超过画幅的 1%–2%，只适用于已明确的对应坐标，不用于跨画幅原图的整屏比较；以 R01 标注后确定的值为准。边角、图标和像素边缘须使用匹配的采样与缩放，不能非等比拉伸。

分别检查构图与比例、像素尺度、色彩明暗、材质形状、中文排版、动态接触六项。可另设 100 分评审表，但“95 分”只能称评审得分，不能等同“95% 像素相似度”。SSIM 或像素差仅辅助定位静态组件差异，动态光照、中文替换和作品变化须分区处理。

交互录像至少包括选择玉料、操作工具、暂停恢复、打开设置、陈列成品和原生 PNG 下载。静态图达到效果后，还要证明变化由游戏状态驱动。

在 1280×800、1920×1080 以及 Windows 125% 缩放下检查中文、点击坐标和边框；800×700 检查面板可访问性。缩放策略须在原生像素清晰度和小窗口可用性之间明确处理，不强行拉满变形。

### 7.3 规则、存档与性能验收

- 保留现有相关测试；按新行为补充“同料两方案”“三阶段不同判定”“一件作品跨视图一致”的规则验证。
- 在每一阶段开始、半途、结束前刷新；恢复后轮廓、色带、线迹和光泽与保存状态一致。
- 验证重复完工、连点、取消后重开、满包返还、存储失败、导入损坏档和旧档迁移。
- 12 块有限原料经试错、错误器型选择和返工后，仍有可完成三种器型首展的恢复路径；覆盖全部先制成同一种器型的情况。本轮已把未拾取掉落写入存档，需继续验证满包、刷新与存储失败重试组合，不再将正常刷新永久丢料作为当前规则。
- Chrome 与 Edge 使用真实输入走完三器首展；记录控制台异常、失焦停止笔触、键盘和原生下载。
- 在指定验收电脑记录机型、分辨率、浏览器、帧时间和加载时间。桌面以接近 60 FPS、操作期间无持续低于 30 FPS 为初始目标，样板实测后冻结预算。
- 优先消除每帧重建纹理、过密粒子与大图重复解码，再处理按场景加载、资源压缩和分包；不把消除构建警告单独当作性能完成。
