# Pixel Jadecraft（像素琢玉）收尾优化任务书

版本：2026-11-18
用途：作为当前分支的唯一收尾执行基线。旧任务书保留为历史记录；本文件覆盖旧文档中的等待确认、旧数量和旧状态。

## 1. 目标与硬约束

把现有的“采矿 → 鉴赏 → 设计 → 三阶段加工 → 落款 → 展出 → 故事回访”做完整、做稳定、做清楚。工作结束前不扩展玩法面，只修正已有功能的视觉、操作、叙事、存档、适配和性能。

硬约束：

- 不新增场景、器型、玉材种类、资源系统、战斗、联机、随机世界、AI 服务或账号后端。
- 不把概念图、静态样稿或生成图当成已实现结果；每个结论都要有游戏内截图、浏览器走查或自动测试证据。
- 保留现有存档兼容、12 格行囊、6 个矿簇/12 块原石、3 种器型、3 阶段加工、3 个故事委托、3 个展位和现有热键。
- 新素材必须有来源与许可记录。来源不清的图片不能进入正式构建；临时截图不能进入提交。
- 不为降低警告而盲目换素材或改变像素风格。包体优化只允许视觉等价压缩、按场景加载、缓存和分包。
- 每轮只改一个可验收面；改动后必须跑自动测试、构建和真实浏览器回归，再关闭任务。

1. 改动文件与不变量；

## 4. P0：必须完成的收尾项

### P0-00 基线锁定与素材清点

**问题**：当前工作区有 v2 素材和临时 PNG，旧文档和 README 的日期/数量落后于代码。
**动作**：建立本轮基线截图；核对 v2 图片尺寸、透明通道、来源和许可；把临时图与正式图分离；更新一处当前状态索引，不重写历史验收。
**验收**：工作区状态可解释；正式构建只引用有来源的素材；临时图不进入提交；README、任务书和验证记录不再混写 134 项与当前 142 项。

### P0-01 工坊全景与师傅姿态

**基准**：附件 01；仓库概念图 09。
**动作**：校正师傅自然俯身比例、双手稳玉和握凿接触点；修正工坊桌面透视与玉料落点；右栏标题保持“琢玉成器”，无作品时不显示误导性的 0% 进度条，入口明确指向开始创作；对白、侧栏和人物不互相遮挡。
**验收**：全景、进入工作台、加工返回三种状态截图中人物比例一致；工具接触玉料；800×700 首屏能看到入口、主要信息和底部对白；刷新和旧档继续不改变存档规则。

### P0-02 矿洞地形、光照与采矿手感

**基准**：附件 02；仓库概念图 01。
**动作**：收敛岩壁 tile 变体、地形接缝、空气区 AO、苔藓、矿灯照亮的金色缝口和凿击青绿粒子；路线指引不能挡住中上平台；保持六簇十二块原石、既有梯井、观察后精准开采、未拾取掉落持久化。
**验收**：从出生点走到六簇并采集/拾取的浏览器记录；连续挖掘、换工具、释放鼠标、刷新读档各有证据；不出现穿墙、重复产出、掉落丢失或指引遮挡。

### P0-03 展厅布展与文字清晰度

**基准**：附件 03；现有展厅与三个展位。
**动作**：展柜画布只渲染器物；名称、材质、工艺、故事和“更换/细看/策展”放到展柜下方木铜铭牌或 DOM 面板；避免把中文缩放进 480×480 画布；保持三展位、灯光主题、移动/替换/移除和唯一作品引用。
**验收**：三展位空/有作品/替换/移除各一张截图；中文在 800×700 和窄宽窗口可读；刷新后不重复作品、不丢展位、不制造虚假展签。

### P0-04 三阶段加工与吸底操作栏

**基准**：附件 04；现有 `polishing-view`、`creative-view`、`piece-renderer`。
**动作**：稳定左工具栏、中央深绿绒垫、右指标栏的双栏结构；取消、保存、完成固定在底部可达区域；让 Satin/Gloss 的粗糙度、细磨和局部高光形成可见差异；保留逐笔撤销、阶段重做、保存退出、返工取消恢复。
**验收**：800×700 首屏无需滚动即可操作当前工具和底部按钮；三阶段各完成一件实际作品；两种表面意图截图差异清楚；鼠标快速移动和事件频率变化不改变结果；刷新后进度、撤销和返工恢复正确。

### P0-05 玉文化馆与鉴赏观察

**基准**：附件 05；现有博物馆 4 个分厅和来源故事。
**动作**：用精细像素 sprite 替换仍显粗糙的代码多边形；放大与侧光切换保持细节；“收藏灵感”入口明显且只记录真实观察；原石观察圈注、热点、知识题和来源说明保持持久化。
**验收**：至少一件馆藏和一块自采原石完成放大、侧光、观察、收藏、返回；刷新后观察和灵感不重复；640px 窄宽与 800×700 不出现遮挡、溢出或不可达按钮。

### P0-06 旧玉来信与回访

**基准**：附件 06；现有 `story-view` 与 heirloom 规则。
**动作**：把鱼佩、红绳、微尘、划痕和信件线索做成可读的像素画面；左侧信件与三线索，右侧修护或另作伴佩；处理结果必须引用真实的清洁、保留旧痕、换绳和纹样证据。
**验收**：两条合理路线都能完成；回访、展签和后续请求记住具体处理；错误或未完成证据不能提前结算；刷新、导出/导入后状态一致。

### P0-07 玉印雕纹与试印

**基准**：附件 07；现有 `seal.js`、雕纹台和作品导出。
**动作**：雕纹台与试印台左右并排；显示试印手记；蘸朱后让白文/朱文结果按真实印面镜像对照；保留返雕、再试印和实际表面读取。
**验收**：同一印面经过两种真实加工后输出不同印迹；试印结果不来自预设换色；刷新后表面和印迹可重建；PNG 只包含真实刻痕。

### P0-08 夜窗落款与纪念卡

**基准**：附件 08；现有落款/导出流程。
**动作**：使用夜窗、红木座、月夜山峦、暖灯笼和轻烟承载成品；落款最多 24 字；导出 PNG 时把成品、材质、工艺、落款和必要展签组合成完整纪念卡。
**验收**：空落款、24 字、超长输入均有明确结果；导出图尺寸和内容固定；作品返回展厅后引用同一作品 ID，不生成副本。

### P0-09 行囊、图鉴与铭牌

**基准**：附件 09；现有 `ui.js`、`icons.js`、图鉴与背包。
**动作**：12 格木框槽位、金色选中状态、立体像素器物图标和羊皮纸详情卡统一；材质、来源、观察、加工记录和收录路径分层显示；Canvas 缩略图与文字分离。
**验收**：空槽、原石、加工中、成品、馆藏条目各有截图；键盘快捷键和鼠标操作一致；中文不糊、不裁切、不把演示占位数值当成正式系统。

## 5. P0：跨模块可靠性门

- **输入与坐标**：鼠标按下/拖动/松开、离开画布、快速移动、窗口缩放、键盘热键不会产生粘连笔触、重复结算或错位点击。
- **存档与迁移**：新档、旧档、损坏档、导入/导出、返工取消、阶段保存、浏览器刷新均通过；保存失败保留可玩的内存进度，重试后可落盘。
- **暂停与声音**：设置、任务、背包、鉴赏、加工弹窗打开时冻结对应输入和计时；页面隐藏、暂停和恢复不重复播放；音乐与音效分开调节且偏好不覆盖损坏的游戏存档。
- **窗口与可达性**：至少验证 1280×720、1024×768、800×700 和窄宽窗口；主要按钮有可见焦点，文字有实际用途，`prefers-reduced-motion` 下不依赖持续动画才能完成操作。
- **回归矩阵**：每个场景至少做一次“进入 → 操作 → 返回 → 刷新 → 继续”；每次记录入口、尺寸、结果和截图路径。

## 6. P1：在 P0 之后做的深度优化

### P1-01 资源与加载

- 对现有 PNG 和字体做无损或视觉等价压缩，保留原件和哈希记录。
- 按场景懒加载或分包，减少首屏加载；不改变像素尺寸、颜色层次和清晰度。
- 测量首屏可操作时间、场景切换时间、内存峰值和重复进入是否命中缓存。
- 处理 Vite 大 chunk 警告；没有真实收益的分包不合入。

### P1-02 运行稳定性

- 对素材加载失败、存储配额不足、PNG 导出失败、字体加载失败提供可恢复路径。
- 运行时错误不得让已保存的作品、原石、展位或设置消失。
- 构建后用 `dist/` 预览而不是只用开发服务器验证一次完整主线。

### P1-03 文字与信息

- 统一“开始创作、保存、完成、返回、细看、更换、收藏灵感”等动作词；按钮文字直接说明结果。
- 展签、知识卡、师傅对白只解释当前操作或真实来源；删除重复提示和占位文案。
- 中英文只保留必要的品牌或素材标签，游戏操作与文化说明以中文为准。

### P1-04 证据与交接

- 每完成一个 P0/P1 任务，在 `docs/validation/2026-11-18-final-polish/` 新增或更新一份记录：改动、命令、截图、差距、结论。
- 任务书只保留当前状态；历史记录不删，README 只链接当前基线和历史证据入口。
- 提交前运行 `git diff --check`，检查大文件、凭据、未跟踪临时图和 `.gitignore` 命中情况。

## 7. 固定执行循环

每个工作循环按以下顺序执行，完成后自动进入下一个未关闭任务：

1. 读取当前状态和上一个任务的证据，确认没有覆盖已有未提交工作。
2. 只选择一个 P0/P1 任务，先写清不变量和可观察结果。
3. 修改实现或素材；不顺手加入冻结清单中的新点子。
4. 跑相关单测；再跑 `npm test` 和 `npm run build`。
5. 启动生产预览，用独立浏览器会话走查入口；在 1280×720、1024×768、800×700 和窄宽窗口取截图。
6. 对照概念图/附件 HTML，记录“已对齐、仍有差距、未验证”，不使用主观的“看起来差不多”关闭任务。
7. 更新验证记录和任务状态；只有证据齐全才标为 `完成`。
8. 检查工作区，明确哪些文件属于本任务，哪些继续留在待处理区。

建议的代理分工：一个代理查视觉与素材证据，一个代理做浏览器回归，一个代理查状态/性能；主代理统一改动边界、测试和交接。代理输出只作为证据输入，不能绕过本任务书的验收门。
