## 1. 本轮目标与范围

完成侧视矿洞的可玩垂直切片，然后优化矿洞画面和操作反馈。

玩家能够移动、跳跃、瞄准、挥镐、挖通土石、接近玉脉、拾取原石、返回工坊并继续探索。碰撞、渲染和挖掘共同读取同一份运行时地形。

沿用以下约束。

- 世界为 60×32 格，每格 32×32 显示像素，总计 1920×1024。
- tile 素材为 16×16、2× 显示。视口为 960×540，相机跟随且整数像素取整。
- 自定义碰撞和重力，复用 `canStand()`、`moveMiner()`、`advanceSwing()`，按需要调整实现。
- 材料结算复用 GameStore 和 `addMaterial()`。暂停复用 PauseGate。
- 使用现有测试框架和依赖。
- 工坊、打磨试玩、其他场景及公共面板保留现有行为。

本轮涉及矿洞玩法、矿洞局部视觉、存档兼容及必要接线。战斗、体力消耗、季节昼夜、工具升级、交易、移动端触控继续留在后续范围。

## 2. 地形生成与数据语义

| 值 | 类型 | 可挖 | 所需镐数 | 掉落 | 阻挡 |
| --- | --- | --- | --- | --- | --- |
| 0 | AIR | — | — | — | 否 |
| 1 | DIRT | 是 | 2 | 碎屑 | 是 |
| 2 | STONE | 是 | 3 | 碎屑 | 是 |
| 3 | JADE_VEIN | 是 | 3 | 1 块对应玉材 | 是 |
| 4 | BEDROCK | 否 | — | — | 是 |

地图按确定顺序生成，坐标均为从 0 开始的 `(column,row)`。

1. seed 固定为 `20261111`。内区行 1–5 为 AIR，行 6–13 以 DIRT 为主，行 14–30 以 STONE 为主。
2. 对土石区应用 v3.0 的 hash，结果大于 0.94 时设为 AIR。

   `hash(c,r) = ((c*374761393 + r*668265263 + seed*1442695041) >>> 0) % 1000 / 1000`

3. 起始洞室固定覆盖列 1–8、行 23–26，设为 AIR。玩家出生点采用 v3.0 指定的脚底坐标 `(160,832)`，其所在列 5、落脚线为行 26 的下沿。行 27 对应起始地面保持实体。
4. 放置六处玉脉簇及周边 STONE，保护出生洞室。
5. 最外一圈统一设为 BEDROCK，边界规则优先于上层 AIR 规则。

| 簇 | 左块坐标 | 右块坐标 | 材质 |
| --- | --- | --- | --- |
| C1 | (10,11) | (11,11) | nephrite |
| C2 | (28,13) | (29,13) | jadeite |
| C3 | (45,18) | (46,18) | nephrite |
| C4 | (20,21) | (21,21) | jadeite |
| C5 | (38,27) | (39,27) | nephrite |
| C6 | (52,29) | (53,29) | jadeite |

周边 STONE 表示玉脉两块外侧一格的包围圈，六簇总计恰好 12 个 vein，两类各 6 块。hash 只用于确定性地图生成。

为每块 vein 分配稳定来源 ID，例如 `C1-L`、`C1-R`。ID 同时用于掉落物与采集记录，不能依赖临时对象引用。

地图生成结果应带有明确的 tile、簇及出生点信息。编辑地形只修改运行时数组，随后更新对应表现与碰撞。

删除旧固定矿点的冷却、再生和 begin/hit/cancel 流程，保留仍有调用者依赖的有效能力，完成调用方迁移后清理旧接口。

## 3. 重力、碰撞与六簇可达性

- 水平移动使用 A/D 或左右方向键，速度为 176 px/s。
- 空格为落地后单次跳跃，初速度为 -420 px/s，重力为 1200 px/s²。
- W/S、上下方向键用于现有梯子攀爬，沿用可用的梯子能力。离开梯子恢复重力。
- 角色位置统一以脚底为锚点，明确精灵缩放后的尺寸和实际碰撞盒。检查头顶、身体、脚底及地图外侧碰撞。
- 使用分步移动或现有等价方法处理大 delta，防止穿墙。撞顶后停止上升，落地后清零下落速度。
- `canStand()` 每次读取当前 map，挖开后立即可通行。

原 v3.0 的天然洞比例及埋藏坐标无法单独保证重力玩法可达。阶段 0 必须提出并固定一条确定性探索路线，可复用梯子和增加必要的 AIR 通道，使玩家能接近六簇、完成挖掘并返回出口。路线保持 12 个 vein 及其坐标，保留各簇需要玩家挖开的岩壁。

将路线、梯子位置和生成顺序写入实现说明。验收必须用真实移动、跳跃、攀爬和挖掘走通。仅用“把所有土石当作可通行”的 flood fill，无法证明实际可达。

## 4. 瞄准与挖掘

| 动作 | 输入与行为 |
| --- | --- |
| 鼠标选格 | 使用相机转换后的世界坐标定位 tile |
| 鼠标挖掘 | 左键按住连续挥镐，松开停止 |
| 键盘挖掘 | E 对角色当前水平朝向的相邻格挥镐，按住连续 |
| 跳跃 | 空格独立处理 |
| 高亮 | 有效目标显示 1px 亮绿 `#8FD46A` 方框 |
| 其他快捷键 | 沿用 Esc / B / J / G / M / F |

挖掘距离为 48 px。距离从角色碰撞盒中心计算到目标格最近点，避免中心距离导致紧贴地面的格子无法选中。对目标做范围、实体、可破坏性及遮挡检查，阻挡射线上的第一个实体格才可挖。

鼠标处于画布内时优先使用鼠标目标，键盘 E 使用朝向目标。目标来源和高亮保持一致。鼠标坐标需覆盖画布缩放、页面滚动和相机移动。

挥镐流程如下。

1. 有效输入与有效目标开始一次挥镐，固定该次目标。
2. `advanceSwing()` 累计有效游戏帧时间，每 320ms 完成一镐。
3. 完成一镐才给目标 damage +1，并复用现有采矿命中音。
4. 按 damage / hardness 显示无裂纹到碎裂前的四档覆盖层，具体帧映射保持单调。
5. 达到 hardness 时将 tile 改成 AIR，生成 6–8 个、寿命 400ms 的碎屑。
6. JADE_VEIN 额外生成一枚玉材掉落物，其他土石只生成碎屑。

切换目标、松手、离开画布或中断输入会取消当前未完成的一镐，已完成镐数对应的 damage 保留。连续挖掘不得同帧对同一块重复破坏或生成重复掉落。

挥镐裁决继续使用有效帧累计时间。暂停、恢复及失焦期间清理按键与指针按下状态，恢复后等待新的输入。

## 5. 掉落、拾取与满包

- 每块 vein 固定掉 1 块对应玉材。
- 掉落物采用 8×8 显示像素玉色图形，两帧上下浮动。
- 玩家碰撞盒与掉落物距离在 28 px 内且路径可接近时自动拾取，调用现有 `store.addMaterial()`。
- 拾取成功后移除掉落物并显示获得反馈。`addMaterial()` 返回失败时保留掉落物。
- 背包 12/12 时仍可挖开 vein，掉落物保留并提示“行囊已满，请当场腾出空位；刷新会丢失未拾取玉料”。提示需要节流。
- 掉落物位置应允许真实角色接近。根据实际碰撞盒验证挖开相邻格后的拾取距离，必要时将掉落生成在破坏格靠近玩家的可达位置。
- 离开矿洞再进入，保留地形、damage 和未拾取掉落物。刷新后按存档边界重建。

正常清空存档开局可采得 12 块玉材。已有旧档的玩家可能已有原石或消耗记录，验收中的“最终 12/12、各 6 块”只用于干净新档。

满包验收使用专门准备的合法测试状态，并用现有材料消费入口腾出空位。若正常入口尚不支持消费，测试通过 Store 模拟消费并如实记录，公共 UI 的完整满包流程保留为待验收。

## 6. 存档修订建议与兼容

本节需要用户确认后实施。

v3.0 只保存 `mineClusters boolean[6]`，在两块全破坏后标记完成。只采一块就刷新会重新生成该块，已拾取材料同时保留，因而可重复产出。两块全破坏且尚未拾取时刷新，按原规格会丢失两枚掉落。

建议保留 `mineClusters`，补充每簇两块的永久破坏标记，例如 `mineVeins boolean[6][2]`。

- `mineVeins[i][j]` 在对应 vein 破坏时置 true，表示该来源已消耗。
- `mineClusters[i]` 等于该簇两枚标记都为 true。
- 刷新后已破坏 vein 所在格生成为 STONE，剩余 vein 保留。
- 背包材料继续由现有 Store 保存。地形、damage、粒子和掉落物保留为会话数据。
- 未拾取掉落物刷新丢失的行为沿用 v3.0，并在界面说明。
- 单块标记、簇标记与现有材料结算通过 Store 管理，覆盖保存失败提示、重试、备份与导出导入，避免只有内存修改成功却展示“已保存”。

兼容规则应覆盖以下情况。

1. 旧档两个字段都缺失，补全 false，保留原背包与成品。
2. 只有合法的 `mineClusters` 时，true 对应两块均 true，false 对应两块均 false。
3. 新字段长度、内层长度和元素类型严格校验。
4. 两字段同时存在且矛盾时拒绝导入并走现有损坏存档提示，防止静默重置资源。
5. 新游戏、继续、导入及检查点恢复触发对应的矿洞会话重建，普通场景往返保持会话。

阶段 0 先汇报该建议并等待确认。确认前可以完成与该决策独立的渲染、地图及操作检查。用户若选择保留 v3.0 原规则，交付中明确记录单块刷新可重复产出的行为及验收边界。
