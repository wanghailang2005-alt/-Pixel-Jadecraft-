# Pixel Jadecraft（像素琢玉）项目计划

更新时间为 2026 年 11 月 11 日，首版交付目标日期为 **2026 年 11 月 30 日**。

## 已确认的设计

采用 Phaser 4.2.1、Vite 8.3.7 和 JavaScript ES Modules，制作浏览器运行的 2D 像素玉文化游戏。核心流程为 **采矿 → 鉴赏 → 三阶段加工 → 定制 → 图鉴收录 → 展厅陈列**。

| 模块 | 首版交付范围 |
| --- | --- |
| 矿洞 | 1 张地图、6 个矿点、2 类玉材 |
| 鉴赏 | 观察热点、知识提示、6 道题 |
| 工坊 | 玉璧、玉鱼佩、玉印，三阶段加工 |
| 定制 | 3 类纹样、配色、祝福语、图片导出 |
| 图鉴 | 6 个器物条目、文化说明与来源 |
| 展厅 | 1 个等距房间、3 个可布置展位 |
| 基础系统 | 菜单、背包、任务、本地存档、声音设置 |

以上完整七模块及数量已获用户确认。课程知识融入各模块，具体知识文案与来源需在制作时核验。

## 开发顺序

1. 建立菜单、场景切换、公共游戏状态、背包和存档基础。
2. 实现矿洞移动、交互采集与材料入包。
3. 接入鉴赏热点、知识提示和题目反馈。
4. 实现琢形、雕纹、抛光三个加工步骤及成品结算。
5. 实现纹样、配色、祝福语与图片导出。
6. 将成品接入图鉴、展厅陈列与任务进度。
7. 先完成一件玉器从采集到展出的完整流程，再补齐七模块的全部数量。
8. 补齐正式美术、声音和知识来源，完成主线及边界场景验证。

## 待细化的规则

- 矿洞操作与资源规则（已定默认值，试玩后调整）：16×16 逻辑 tile 以 2× 显示为 32×32，60×32 格世界为 1920×1024 显示像素，使用 960×540 跟随镜头和整数像素取整。方向键 / WASD 四向移动，空格 / E 就近挥镐，6 个固定矿点各产出 1 块和田玉或翡翠原石。角色帧为 32×48，每方向按 4 帧行走、2 帧挥镐排列，方向顺序为左 / 右 / 下，共 18 帧，绘制按 8px 网格对齐。矿点依次完整 → 裂纹 → 可采 → 开采中 → 采空 → 再生，初始完整与裂纹各 200ms，挥镐共 320ms，采空冷却 30 秒，再生 400ms 后可采。矿点状态由 runtime 闭包 Map 在场景切换间保留，冷却按实际经过时间计算，刷新与更换游戏会话重置。
- 琢形容差、雕纹交互、抛光覆盖率、完成阈值及评分公式。
- 三类纹样的具体内容、祝福语长度和导出图片规格。
- 背包容量、加工中断处理、自动保存时机及存档恢复行为。
- 问答与任务完成条件的关系。
- 主线故事、引导文案和成品展签。
- 课程对 AI 功能、说明文档与演示材料的具体要求。

这些规则应在实现前形成明确默认行为，并在试玩中调整。后续修改已确认的模块与数量时，应更新本计划和验收范围。

## 矿洞正式素材替换契约

- 人工用 Tiled 导出 `public/maps/mine.tmj`，采用有限正交地图，tilewidth / tileheight 为 16，width / height 为 60 / 32。图层为 ground / walls / decor，walls 的碰撞 tile 设置布尔属性 collides=true。当前加载器读取原点对齐的未压缩 JSON tile 数组及嵌入的 tileset 定义，PNG 纹理统一绑定固定的 mine-tiles 图集。
- 对象层 oreNodes 包含六个 type=Ore 对象，字符串属性 nodeId / material 与 `src/mining.js` 的六个 MINE_NODES 对应。spawn 包含一个 PlayerSpawn 点对象。编辑器对象坐标为逻辑像素，运行时统一乘 2 得到世界坐标，矩形对象采用中心点。
- `mine.tmj` 存在时，由 `load.tilemapTiledJSON` 和原生 tilemap 图层加载，使用 `addTilesetImage`、`createLayer`、`setCollisionByProperty` 与 `getObjectLayer`。适配器提供与二维数组路径一致的矿点、出生点与 canStand 碰撞接口，结算继续走已有 GameStore。缺席时采用 MINE_MAP 与 Graphics 图集。地图由固定路径的构建期 glob 发现，加入文件后重启开发服务或重新构建即可。
- LibreSprite 导出透明背景等距网格 PNG，margin / spacing=0，行优先排列，关闭 JSON Atlas 与 extrude。`src/assets/tiles-mine.png` 使用 16×16 帧，运行时 2× 显示。`src/assets/player-32x48.png` 使用 32×48 帧，0–5 为左向、6–11 为右向、12–17 为下向，各方向前 4 帧行走、后 2 帧挥镐。两个固定 import.meta.glob 路径与加载帧规格已接通。
- 人工出图清单包括岩壁顶 / 面 / 内角 / 外角、碎石地面、苔藓边缘、木支撑梁、木梯、矿车、火把、发光玉脉六态、断裂石柱、水洼、木箱、绳索，以及矿工 18 帧。当前矿点六态和碎屑采用 Graphics 表现，正式矿脉帧映射留待素材交付时接入。

## 设计来源

矿洞的唯一视觉基准采用 1024×559 的 01 图，方向为侧视横版、深蓝灰岩与苔藓、中央洞口冷光、两侧石柱、青绿自发光玉脉、木矿车，以及戴矿灯帽的矿工举镐和碎屑粒子。01 用于确定氛围、元素清单与配色，正式 tileset 按素材替换契约独立生产。[01 矿脉探索与原石采集](concept-art/01-mine-exploration.png)

正式素材替换轮次按顺序采用岩壁 #2B3A42 / #4A5A62、苔藓 #3E6B45、玉光 #4FC98A / #7FE3B0、木 #8B5A2B、底 #101C1B、字 #E8DCC0。洞口冷光在 01 原图以左上角为原点取样 (560, 160)，确定为 #8AABA9。占位阶段继续沿用 v1.1 代码现有 14 色，正式素材替换当日统一切换矿洞绘制配色并停用这套占位色值。

01 的 HUD 为顶部 HP / JADE / LEVEL 状态条、左下三格快捷栏及方向键 / A 按钮。当前已改为顶部状态条与左下三格工具栏，方向操作采用键盘提示；尚未加入触屏方向按钮。

本项目参考星露谷 / 泰拉瑞亚，仅限于资产生产规格（16×16 tile、sprite sheet、四向行走帧、8px 网格）与交互手感（工具动作帧、粒子与音效反馈、热键栏）。题材、配色、中式回纹 UI、等距工坊与展厅仍以概念图 01–10 为准，维持“按原图复刻 / 基础 UI 95% 接近”。矿洞采用侧视横版，参考泰拉瑞亚洞穴探索，配色沿用现有矿洞代码。范围排除可破坏地形、季节昼夜动态光照与战斗系统。本轮角色先接入左 / 右 / 下三向帧，上行沿用下向帧。

2026 年 11 月 11 日的视觉与交互访谈结果见[视觉与交互设计框架](../DESIGN_SYSTEM.md)，包括工坊斜视全景与俯视加工近景、工具操作、弹窗暂停、中式等距展厅及三张样稿要求。新增四张参考图见[概念图集](concept-art/README.md)。分辨率、精确组件尺寸、字号与完整色表通过样稿验证后确定。
